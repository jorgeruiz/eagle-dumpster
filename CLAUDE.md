### 2a. Escribir tokens

Cuando Jorge elija, escribe `tokens.css` con EXACTAMENTE este formato:

```css
/* Generated by Code — verified by verify-design.sh */
@theme {
  /* Reset Tailwind defaults */
  --color-*: initial;
  --radius-*: initial;
  --font-*: initial;
  --shadow-*: initial;

  /* Color tokens */
  --color-bg: #______;
  --color-surface: #______;
  --color-primary: #______;
  --color-on-primary: #______;
  --color-text: #______;
  --color-text-muted: #______;
  --color-border: #______;
  --color-error: #DC2626;

  /* Typography */
  --font-heading: 'NombreFuente', sans-serif;
  --font-body: 'NombreFuente', sans-serif;
  --font-mono: 'NombreFuente', monospace;
  --heading-tracking: -0.02em;
  --heading-weight: 700;

  /* Type scale */
  --text-xs: 0.75rem;
  --text-sm: 0.875rem;
  --text-base: 1rem;
  --text-lg: 1.125rem;
  --text-xl: 1.25rem;
  --text-2xl: 1.5rem;
  --text-3xl: 2.5rem;
  --text-4xl: 3.5rem;

  /* Shape */
  --radius: 8px;
  --border-width: 1px;

  /* Layout */
  --content-width: 1280px;
  --section-y: 5rem;
  --gutter: 1.5rem;

  /* Motion */
  --duration-max: 300ms;
  --easing: cubic-bezier(0.4, 0, 0.2, 1);
}
```

Los `initial` de `@theme` son OBLIGATORIOS — desactivan las clases default de
Tailwind para que el sistema sea cerrado. Sin ellos, clases como `bg-blue-600`
o `rounded-lg` compilan y rompen la consistencia.

Importa `tokens.css` en `globals.css` con `@import './tokens.css';` antes de
escribir un solo componente.

### Escribir DESIGN.md

Junto con `tokens.css`, escribe un `DESIGN.md` que documente:
- Las prohibiciones (hex fuera de tokens, clases Tailwind default, etc.)
- Los tokens con su uso
- Tipografia (familias, escala, carga de fuentes con `next/font/google`)
- Forma (radius, shadows, glass)
- Densidad y espaciado
- Motion (budget, propiedades permitidas, duracion)
- Accesibilidad (contraste, focus visible)

### Regenerar verify-design.sh con tus tokens reales

El `verify-design.sh` incluido en el bundle es un scaffold generico. Despues
de escribir `tokens.css`, REESCRIBE `verify-design.sh` para que verifique
contra TUS tokens reales:

- Hex fuera de tus 7 colores + #DC2626 (error) → FAIL
- `rounded-*` de Tailwind cuando tu radius es 0 → FAIL
- `shadow-*` cuando tu shadows es none → FAIL
- `framer-motion` importado cuando tu budget es css-only o none → FAIL
- `font-family` fuera de tus variables → FAIL

**Contraste — OBLIGATORIO, no opcional:**
El verify regenerado DEBE incluir estos checks de contraste. Sin ellos, el
verify esta incompleto y no se considera valido:
- `--color-text` vs `--color-bg` → ratio >= 4.5 (WCAG AA)
- `--color-text-muted` vs `--color-bg` → ratio >= 3.0
- `--color-text` vs `--color-surface` → ratio >= 4.5
- `--color-on-primary` vs `--color-primary` → ratio >= 4.5
- Si CUALQUIER par falla → FAIL. No ignorar, no skipear, no allowlistear.

Nota: estos checks cubren los tokens globales. Si usas texto sobre un hero
con imagen/gradiente de fondo, el contraste TAMBIEN debe garantizarse en el
componente (overlay oscuro, text-shadow, o fondo solido parcial). El verify
no puede checar eso automaticamente, pero el AUDITOR (paso final) si lo
revisa visualmente.

El script del bundle solo checa lo generico. El tuyo debe checar lo especifico.

## Logica de correccion — mecanico vs criterio

Despues de recibir el reporte del auditor, clasifica cada FALLO:

### Fallos MECANICOS — Code corrige solo
